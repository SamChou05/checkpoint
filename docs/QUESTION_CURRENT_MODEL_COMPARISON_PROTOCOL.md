## Bounds and failure handling

- Eight cases, two model arms, at most two calls per case/arm: **32 provider calls maximum**, including attempted calls with unknown usage. Do not transfer unused calls to additional work.
- Each complete serialized Converse request is at most **32 KiB (32,768 UTF-8 bytes)**. Across 32 calls the maximum serialized request allowance is 1,048,576 bytes. Reject oversized requests before dispatch; never clip the question or context to fit.
- Use one SDK attempt per call, a three-second connection timeout, a 100-second read timeout and a 240-second deadline for each request's worker. Persist the dispatch record before invoking the provider. Terminate and reap a timed-out worker, confirm process-group cleanup, and stop without starting another job.
- No retry, repair, replacement, top-up or resume is allowed. A normal semantic veto skips that arm's reviewer. A usable completed text response with malformed JSON or invalid stage content counts as unavailable for assessment; skip its dependent stage and continue only the already-frozen next jobs. Keep the runtime's exact status and quality reasons: `completed` alone does not establish valid JSON or semantic correctness.
- Provider/transport failure, an invalid provider response envelope, a stop reason other than `end_turn`, unknown usage, worker deadline, cleanup failure or persistence failure stops the run. Preserve partial records, distinguish attempted from unattempted jobs, and retain unknown usage; do not silently rerun the plan.
