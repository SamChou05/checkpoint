# Task-only numerical full-worker successor: proposed one-shot qualification

**Draft only. No AWS or model calls for this candidate.** This trial uses the exact three five-slot normalized jobs from the frozen current-source worker successor: numerical, Python, and mixed arithmetic/English. That run returned 9/15 (0/5 numerical, 5/5 Python, 4/5 mixed) and failed the 14/15 release gate after its numerical five-item author exhausted 16,000 output tokens. The separately locked numerical task-only pilot returned 5/5 compiler-proven questions in 127.684 seconds. Those runs are historical observations, not causal estimates.

The candidate starts at `origin/main` commit `187bbb2d0cb43870979448baf4e5784c482ee513` and includes the reviewed exact-goal batch-scope source through `87e14d0324486d64b0fe9c52e39a68aed3a1ab28`. Its only trial-environment additions are `QUESTION_CONSTRUCTED_AUTHOR_BATCH_SIZE=3`, `QUESTION_CONSTRUCTED_AUTHOR_BATCH_GOAL_SHA256=afad55f2475381992d1355945ef521da72d3170f06d6ea83670f07ee868c46f0`, and `QUESTION_TASK_ONLY_NUMERICAL_GOAL_SHA256` at the same digest. This scope matters because the previously unscoped cap would also reduce the unallocated Python author's first batch to three; missing, blank, or conflicting scope is now rejected when task-only authoring and the cap are configured together. The numerical job alone uses versioned native `question_author_tasks_v1` and initially requests three typed tasks; its later top-up targets the remaining verified count. The Python and mixed jobs retain their five-item `question_author_constructed_v1` author requests. Models, adaptive/high reasoning, 16,000 combined output tokens, authored-solution feedback, six-call per-job limit, three attempts, and other settings match the frozen predecessor. None of these flags is a rollout default.

Preserve all 15 original slots and 18 per-job call slots in one exclusive, no-resume capture before credentials. Each of three jobs gets its own 240-second deadline, at most six durable provider-call reservations, a read timeout clamped to remaining time and at most 200 seconds, a three-second connect timeout, and one SDK attempt per Converse. Fsync the reservation, exact request, and attempted-dispatch marker before sending. Capture actual author, compiler, sanitizer, solver if needed, final audit, top-ups, and partial returns without replacing worker decisions. A native schema rejection, timeout, or failed reviewer is recorded as a failed attempt; no fallback or replacement trial is allowed.

The reviewed default AWS login profile, account `239342516379`, exact STS and Bedrock Runtime endpoints in `us-east-1`, AWS CLI 2.33.15, config fingerprint, and one frozen credential session are pinned. An independent one-shot launch precheck may make one STS identity request and at most two bounded Signin refresh operations, with zero model calls. It requires at least 840 seconds of exported credential life. Freeze and execute require at least 810 seconds remaining on that precheck snapshot; execution requires its own snapshot to have at least 780 seconds, covering three 240-second job windows plus 60 seconds of setup and inter-job overhead. Recheck credential lifetime before each signed call. Any slower review must happen before the launch precheck; do not repeat it after an ambiguous attempt.

The prespecified qualification criteria remain the predecessor's: at least 14/15 original slots, at least 4/5 from each job, at least six compiled returns including four numerical and two mixed, at least one mixed English prose return, and at least one returned Python `and`/`or` operand-return item. Every returned item must have exactly one correct literal answer, four distinct offered answers, sound main and wrong-choice teaching, valid scope/difficulty/novelty, proper policy-7 or policy-8 provenance, and zero unresolved independent content uncertainty. The 240-second and call budgets must hold for all jobs. After capture, project all original slots to a keyless worksheet and lock two independent answer and six-pair judgments for each returned item before joining keys or teaching.

Before any AWS operation, independently review the committed harness, socket-blocked tests, exact source and predecessor hashes, all three first author prompts, task-only and constructed schemas, role separation, credential/endpoint safeguards, and frozen criteria. Run offline preflight and the full backend suite. Only after an explicit independent GO may the operator run the one-shot freshness precheck, freeze the reviewed draft digest, and execute once. The outcome is a single full-worker sample, not a population reliability estimate or qualification of deployment, SQS, DynamoDB, inventory refill, or default settings.

The candidate source passed 1,374 backend tests. The adapted harness passed 55 socket-blocked tests and an offline preflight with zero AWS/model calls. The preflight is separate from the AWS freshness precheck and does not authorize it.
