# Mixed-job author truncation: bounded diagnosis

The mixed job returned **0/5** because its first author response exhausted the 16,000-output-token allowance before it formed a complete native JSON value. The single Converse call took 162.346 seconds, reported 5,387 input and 16,000 output tokens, and ended `max_tokens`. Its visible text is 32,871 characters: it contains 37 complete array rows (three quantitative, then 34 English prose) and stops inside a 38th prose row, without closing the array or object. The runtime recorded `provider.output_truncated=1`, started no solver or reviewer call, and left all five original slots unfilled. It correctly did not salvage apparently complete prefixes from a truncated, unvalidated native response.

The frozen request asked for exactly five items with a 3 arithmetic / 2 English skill allocation. Both the system and user prompts explicitly required that count and mapped skill/objective tags. The first three visible quantitative rows carried the arithmetic skill and objective IDs. None of the 34 complete prose rows carried `skillID`, `objectiveID`, or `objective`; applying the current skill-tag validator to those complete rows resolves zero English tags. This is a **counterfactual local check**, not a claim that the runtime admitted or rejected those rows: native decoding stopped before the compiler and sanitizer. The `question_author_constructed_v1` native schema permits an unbounded `questions` array and makes the mapped tags optional in a prose row. It therefore did not constrain the model's overproduction or missing English tags, even though the prompt requested both constraints.

The new numerical-only three-item cap did not apply to this mapped job: the current allocation guard keeps its author target at five. Its actual first author prompt and schema are byte-equal to the frozen predecessor's mixed first request. This sample proves overgeneration and truncation as the immediate failure path; it does **not** prove why the model ignored the count, that the numerical flags caused the mixed failure, or how much of 16,000 output tokens went to the omitted reasoning block versus visible text. A larger token ceiling or a prompt-only reminder is not established as a remedy by this observation.

1. **First test: a mixed-scoped fixed-five native author contract with mandatory mapped tags.** The existing `AuthorSlotContract(5, "constructed_quantitative")` provides five required named slots, so it is the smallest transport change to test against the unbounded array. Require the exact mapped skill/objective fields for this scoped route, and prospectively test the full author → solver → reviewer worker with the unchanged 3:2 allocation and 240-second/six-call limits. This must be scoped away from the numerical task-only route, which requires array cardinality. Earlier fixed-count author-only trials achieved exact row counts but had worse content usability (4/10 versus array 6/10), so structural success alone is insufficient.
2. **If fixed-five content or tags still fail, test allocation-aware 3+2 author passes.** Request three arithmetic slots with an allocation summing to three, then two English slots with an allocation summing to two, retaining the same final 3:2 quota and existing sanitizer/verification. This needs explicit quota slicing and remaining-allocation tests; setting a global three-item cap without slicing would present a target of three alongside five requested assignments. Two fully verified passes can consume the entire six-call budget and must still fit 240 seconds, so a one-shot full-worker qualification is needed before any rollout.
