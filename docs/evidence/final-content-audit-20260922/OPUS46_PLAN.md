# Opus4.6 final-auditor qualification: new three-call protocol

This new trial tests only the model selection for the same final read-only auditor. It does not modify any prior failed evidence or alter the auditor prompt to mention known cases. All eighteen controls are now reused diagnostics. Three calls keep the exact request content, ordering, prompt, count-six native schema and settings from the separate Sonnet adaptive-only plan; only modelId becomes `us.anthropic.claude-opus-4-6-v1`.

The settings remain adaptive HIGH (not max), no temperature, 16000 shared output/reasoning tokens, us-east-1, read75s/connect3s and SDK total attempts1. Read-only preflight confirms the Opus4.6 system profile active and agreement/authorization/entitlement/region available. The earlier model comparison also captured actual native Converse success for this profile. No account agreement, subscription or activation action is part of this trial. Production native model admission still allows only Kimi/Sonnet; this evidence-only direct Converse experiment does not broaden that allowlist. Any later qualified Opus routing would require a separately reviewed final-auditor-only integration.

Opus5 was considered but not dispatched or frozen: its active profile did not establish native capability, its agreement status was NOT_AVAILABLE, and the official model card listed structured outputs unsupported. Those read-only findings are separately preserved. This plan uses the parent-confirmed Opus4.6/high configuration, giving a true modelId-only request delta from the Sonnet qualification.

The three batches run once in original order. Stop all remaining calls after the first provider failure, non-end_turn stop, native shape failure or strict local format failure. No warmups, retries, substitutions, replacements, repairs or extra calls. Preserve all18 planned cases and any unattempted denominator. Semantic failure remains failure, with no alternative prompt or after-output relabeling.

Qualification requires18/18 exact dispositions,9/9 sound payloads accepted,9/9 defective payloads rejected, unchanged accepted originals and all eighteen reasons factually sound and no longer than600 codepoints. Uncertainty fails. Exact duplicate JSON keys and missing/unknown IDs or fields are invalid. Native responses must finish normally. Independent manual reason review is required, beyond mechanical schema/disposition scoring. Provider reasoning text/signatures are stripped from captures; only block counts remain. Credentials remain in memory.

The wrapper pins and imports unchanged helpers from the previous source-independent trials. It creates separate exclusive plan/capture files and reuses the already tested three-call ceiling. It never changes model settings for preceding generation/solver/writer stages. No production code, defaults, environment or account configuration is modified. A diagnostic pass would require fresh end-to-end content/yield qualification before any release. There is no claim of a population accuracy rate or a randomized contemporaneous causal comparison. Parent must approve this plan's exact frozen hash before dispatch.
