# Frozen-plan protocol: read-only final-content gate

The original design is in PROPOSAL.md; SCOPE_AMENDMENT.md records the parent-approved pre-freeze expansion and reason-field clarification. Parent approved that proposal and the exact short auditor-prompt.txt before this plan was prepared. Generating plan.json is an offline freeze; executing requires a separate explicit parent authorization of its exact file hash.

The independently reviewed control packet has eighteen full learner payloads, nine sound and nine defective. Batch 0 contains the three familiar sound/defective families; batch 1 contains the three families whose prior controls were never dispatched. Batch 2 contains the supplemental three pairs for language ambiguity, equivalent wrong answers and representation-sensitive distinctions. The original twelve-case packet remains byte-identical. Within a batch, opaque dense IDs are assigned by ascending SHA256 of the canonical learner payload; no gold or sound/defective label participates in ordering. Paired relationships and provenance never enter provider messages. Every arm sees identical content and ID order. The supplemental batch adds a known grammatical ambiguity and two controlled distinctions absent from the first twelve items; broad-domain accuracy is still not inferred.

Six planned dispatches: batch 0 disabled; batch 0 adaptive high; batch 1 adaptive high; batch 1 disabled; batch 2 disabled; batch 2 adaptive high. The model is us.anthropic.claude-sonnet-4-6. Disabled uses temperature 0.2 and 6000 output tokens; adaptive high omits temperature and uses 16000 shared output/reasoning tokens. Both use native count-six closed identities, read 75s/connect 3s and SDK total attempts 1. Exact provider requests, contract metadata, scope, control bytes, independent gold review, helper/runner/tests/prompt/proposal source hashes and dependency versions are saved in plan.json before dispatch.

The source-independent candidate contract serializes exactly reason then verdict; no generic transport suffix is appended to the approved audit-only prompt. Responses have only audits with six required IDs. The validator rejects malformed JSON, duplicate keys, extra/missing fields/IDs, unsupported verdicts and blank or whitespace-only reasons, and reasons above 600 codepoints. A separate native-schema validation checks the returned object. The selector releases only deep copies of original accepted learner payloads. Content hashes must match; no negative or uncertain item is repaired or rescued. The reason field is an audit summary, never displayed learner feedback.

Qualification is separate per configuration and requires all 18 correct dispositions (nine accepted sound payloads, nine rejected defective payloads), sound item-specific reasons, exact accepted-content preservation, and all three structural/end-turn successes. Uncertain verdicts or uncertain reason quality fail. Correct dispositions with false reasons do not qualify. Independent review of all returned reasons is required, with no after-output relabeling. Actual reason-before-verdict output order is measured rather than assumed.

The first provider failure, non-end_turn stop or strict structure failure terminates the entire experiment. Remaining calls stay unattempted in the denominator. No retries, warmups, replacements, new prompts, changed gold or extra calls. A semantic miss does not stop a structurally valid comparison. Save text responses, model usage and latency; strip provider reasoningContent blocks and signatures while recording their counts. Credentials remain in memory only. The experiment is inactive by default and cannot overwrite existing plan or capture files.

Even a component pass would support only fresh end-to-end qualification of a fourth read-only stage. It is not a production deployment, proof of universal accuracy, paired causal isolation of thinking alone, or evidence that two four-stage passes fit the existing six-call/240-second worker budget.
