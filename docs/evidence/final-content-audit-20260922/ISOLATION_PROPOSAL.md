# Proposed singleton audit diagnostic — not frozen or authorized

The previous final-auditor trials placed three sound/defective counterpart pairs together in one request. Several returned reasons explicitly refer to another item. A possible source of error is cross-item influence: a restriction present in a sound stem may be applied to its unqualified counterpart, or a response may blur the distinct and duplicate distractor sets. A separate possibility is the amount of simultaneous judging. This diagnostic would remove neighboring items and reduce the per-call workload together; it cannot distinguish those mechanisms by itself.

Proposed scope: exactly six calls, one for each unchanged supplemental learner payload in its existing frozen order. Copy the supplemental adaptive request from `adaptive-only-plan.json` (plan SHA `d2a3f563f523f6ddd3f073cc33956cdef89f3cc0e0a3a8c4ac1c76322ceda245`, source request SHA `23fc528c749ad28c5b1f2ccdae5712ff1c7e508bc9e304ba8843743e8a86c6a5`). Preserve the original short auditor prompt and all task scope/model/settings. Each request retains one exact payload, rebinds its trusted input ID to `0`, and replaces the native count-six configuration with `final_content_audit_v1_n1` from the same frozen contract prototype. Gold, labels, counterpart relationships and provenance remain outside provider input. No payload, explanation or answer string changes.

The fixed sequence would be: duplicate wrong value defective; semicolon defective; duplicate wrong value sound; decimal representation sound; semicolon sound; decimal representation defective. These are six reused diagnostics, including known model failures and controls, not new holdouts. No batched baseline call is proposed: the existing frozen batched results remain the comparison reference, not a concurrent causal control.

Use `us.anthropic.claude-sonnet-4-6`, adaptive high, no temperature, 16000 shared tokens, read75s/connect3s, SDK total attempts1, region us-east-1. Keep the nonblank 600-codepoint reason limit and exact closed identity/field/type/verdict checks. Preserve reason before verdict, reasoning-content redaction, in-memory credentials and immutable original-content selection. Exactly six dispatches maximum, no retries, warmups, replacements or extra calls. Stop the entire trial on the first provider failure, non-end_turn, native shape failure or local validation failure; preserve all failed/unattempted items in the denominator. Semantic misses do not trigger replacement or early stopping.

Diagnostic success requires six exact dispositions, all three sound responses retained, all three defective responses rejected, every reason accurate and grounded, every accepted original unchanged, and all six responses within operational bounds. Independent audit must read every returned reason and verify request isolation. Record time and token usage for each item and in aggregate.

This would be a separately frozen diagnostic, not a modification of the failed 22/24 trial or a production qualification. Per-item auditing consumes six calls for this six-item batch, so even perfect correctness here would not establish viable worker throughput or compliance with the production call ceiling. Any later architecture change would need its own explicitly budgeted full-worker test. No production edits or new provider calls are authorized by this proposal. Parent review of scope comes before building/freezing the exact new plan; parent approval of its final hash comes before dispatch.
