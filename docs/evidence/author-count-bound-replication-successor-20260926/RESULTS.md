# Replicated author count trial: structure passed, usability failed

The independently reviewed successor ran once after the [first plan's zero-call setup abort](../author-count-bound-replication-20260926/SETUP_ABORT.md). Its four prespecified author requests all completed, with one Bedrock Converse attempt each and a single in-trial STS identity check of account `239342516379`. All four native responses ended normally, validated against their selected contracts, adapted locally, and contained exactly five original prose rows. Both fixed-count maps had precisely keys `"0"`–`"4"`. An [independent structural replay](STRUCTURAL_REPLAY.md) reproduced the requests, responses, adaptation, admission counts, and blind mapping without another provider call. **This is a structural success, not an MCQ-quality success.** No retry, replacement, top-up, solver, or reviewer call occurred in this author-only trial.

The candidate fails every comparative content gate: **4/10** usable is below the frozen **8/10** minimum, below the array baseline's **6/10**, and lower within both assignment pairs. It qualifies for neither a broader follow-up trial under this plan nor a default/deployment change. The content judgments and source ordinals are in the [archive audit](post-review-archive.md) and [greenhouse audit](post-review-greenhouse.md); the [joint lock](blind-lock.json) protects the two independent keyless reviews before the [unblinding](unblinded-review.json). Uncertainty receives no usable credit.

The archive assignment exposed a deterministic local bottleneck. Although the prompt asks for stems at most 320 characters, seven of ten raw archive stems exceeded the active `MAX_PROVIDER_PROMPT_CHARS=320` gate: array lengths `257, 267, 388, 383, 339`; fixed-count lengths `354, 369, 402, 309, 352`. Replaying the **active `reviewer_written` sanitizer** on all twenty unchanged adapted rows yields archive array 2/5, archive fixed-count 1/5, and greenhouse 5/5 in each arm. This replay does not give semantic credit: the array's second surviving archive item repeats its first hold-blocks-renewal mechanism, and the fixed-count's sole surviving archive item has an unsupported key and false date teaching. [Amazon Bedrock's supported structured-output schema subset](https://docs.aws.amazon.com/bedrock/latest/userguide/structured-output.html) explicitly excludes `maxLength`, so the native grammar cannot enforce this application stem limit. A local reject/top-up or a different bounded authoring task is still needed; truncating a stem could remove a necessary premise.

The two assessors agreed on the answer to all five archive array and five greenhouse array rows, but flagged four fixed-count rows as unavailable or uncertain across the two assignments. Archive fixed-count rows omitted renewal conditions, assumed an unstated renewal term, falsely described a hold restriction, or calculated a due date from an inconsistent term. In the greenhouse fixed-count arm, a question asking *what action* offered two “No alert” responses with different rationales; one assessor could not treat the action as unique. The other nine greenhouse keys aligned with both independent literal solutions. The frozen candidate therefore did not solve the user's distinct-choice or single-answer problem merely by changing the response container.

All ten greenhouse authored explanations refer to raw `Choice a`/`b`/`c`/`d` positions. The active `reviewer_written` path does not retain that author teaching unchanged, so the authored-solution-only freeze gate was not applied in the primary score. If those explanations were shown directly after choices shuffle, all ten would fail the existing answer-label reference guard. The explicit structured key remains the authority for highlighting; prose references cannot safely determine it.
