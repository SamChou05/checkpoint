# Offline replay of the bounded Python Boolean teaching guard

After the frozen author trial was assessed, source commit `602011f` added a local guard for two observed incomplete *generic* claims in authored Python prose explanations. It rejects an unqualified statement that `or` returns the first truthy operand without allowing the last operand when none is truthy, or that `and` returns the first falsy operand without allowing the last operand when none is falsy. It leaves case-specific wording and complete rules eligible. The guard is a conservative pattern check, not a general semantic proof.

An offline replay passed each of the 20 unchanged raw authored rows from `capture.json` to `has_incomplete_python_boolean_rule(prompt, topic, explanation)`. Labels came from the separately locked `post-unblind-assessment-b.json`; no model was called and no trial output or label was edited. All **3/3** rows labeled with these false universal rules were flagged; **0/17** other explanations were flagged. The helper source SHA-256 was `d60e67101ee262bdad8c37c7b29ea319ee1966030fc57b7a8e4a119f9789069c`. The frozen capture and assessment SHA-256 values remain `29883bdbd2be23afe15527adc6a9f199a0cb79c13c6a0203adfb903ddd38ab1a` and `65443d9c671c5964af5f29027029fede6cbba2e476db3d3caadcc6da4e7520cd`.

The integration checkout passed 1,361 backend tests and Ruff. A SAM build copied the new helper into the API, worker and outbox artifacts with source-matching SHA-256. This local fix does not correct the collective-noun ambiguity, reservation explanation error, arbitrary paraphrase duplicates, or any novel false rule outside the narrow pattern.
