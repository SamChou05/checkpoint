# Reviewed-source one-job harness adaptation

The adjacent [harness](full_worker_probe.py) exercises the reviewed mapped candidate source offline. `--preflight` runs socket-blocked tests. The one-shot `--launch-precheck`, `--freeze`, and `--execute` entrypoints are now enabled with exact source, normalized scope, first-prompt, native-schema, identity, and transport pins. Independent review of this launch-enable diff is pending. There is no live precheck, frozen plan, or capture artifact.

The prior [three-job harness](../task-only-full-worker-qualification-20260926/full_worker_probe.py) contained the following hard-coded cardinality assumptions; each was changed here:

| Prior assumption | One-job adaptation |
| --- | --- |
| `new_capture` required three jobs and materialized fifteen question slots and eighteen call slots. | It requires the one `mixed` job, five question slots, and six call slots. |
| `build_plan` required `quantitative`, `python`, `mixed`, their fifteen-slot job fixture, task-only numerical flags, and three initial author prompt/schema pin sets. | It requires the exact prior mixed job alone. Numerical flags are absent. It pins both mapped opt-in digests, the first prompt/schema, and all eleven native contract variants for possible remaining allocations. |
| Author-stage validation treated only the numerical task contract as special and pinned Python/mixed to the predecessor array contract. | The stage requires the exact scoped mapped contract derived from the trusted initial assignment and current remaining quota, including a smaller top-up. The first provider stage must be the mixed author. |
| `reserve` and `Recorder` allowed up to eighteen total reservations/calls. | Both enforce six total, while the per-job `ProviderCallBudget(6)` and original slot ordinals remain intact. |
| `run_jobs` asserted three original jobs and eighteen call slots. | It asserts one original job and six call slots and still forbids resume. |
| `finish` reported fifteen planned questions. | It reports five original questions, including unfilled slots in the denominator. |
| Credential freshness covered three 240-second jobs: 840-second precheck, 810-second launch, 780-second execution. | Thresholds are 360, 330, and 300 seconds for one 240-second job plus margin. |

The existing durable write sequence remains: exclusive capture creation, fsynced reservation, exact request, attempted-dispatch marker, then one SDK Converse attempt. The recorder still checks endpoint, region, model, native contract, prompt, timeout, source/capture integrity, response bounds, credential echo, and safe error identity. It preserves actual author/compiler/sanitizer/solver/reviewer/returned-object provenance. The [tests](test_mixed_worker_probe.py) use the real local worker pipeline with fake model text and block socket connections; they cover the five-slot/three-compiled/two-prose example, durable markers, no resume, credential and deadline checks after request persistence, transport/profile safeguards, source/prompt/capture drift, and response redaction. Scoped fixed-map fixtures produce raw keys `0`–`4`, reject a typed division-by-zero row and request a one-slot `n1` top-up within five calls, and reject missing or wrong mapped tags before solver/reviewer work.

The draft-to-frozen state transition now keeps the launch attempt and precheck digests bound to the exact `draft_offline_ready` plan produced by `build_plan()`. The frozen file differs from that reviewed draft only in its `state` field. `check_plan()` accepts a frozen file only if resetting that field exactly recreates the current reviewed draft, and its on-disk hash matches the caller's expected hash. The mapped assignment tuples are serialized as lists when the draft is built so JSON round-tripping cannot create a false mismatch. Socket-blocked fake-client tests exercise precheck → freeze → execute to five returns, one-shot artifact guards, altered draft/record/frozen plan, wrong account, and credential/deadline failures after exact request persistence. These tests patch external credential boundaries within the test process; they make no AWS or model calls.

The transition patch passed independent review. The reviewed candidate source passed 1,380 backend tests, and the offline draft/harness suite passed 42 socket-blocked and pin checks in this checkout. The launch-enable change needs independent review before any live precheck. This file is an adaptation record, not a launch approval.
