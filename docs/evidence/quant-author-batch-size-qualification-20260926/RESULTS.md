# Three-item numerical author pilot: no truncation, no compiled returns

The one-shot candidate reduced the first constructed-numerical author request from five items to three while keeping the prior numerical assignment, native array contract, model, adaptive/high reasoning, verification route, 16,000-token allowance, six-call ceiling, and 240-second deadline. Both author calls completed normally, avoiding the earlier five-item `max_tokens` stop. The pilot nevertheless returned **3/5** original questions, all authored prose; **0/5** had deterministic compiler provenance. It fails the frozen **at least 4/5 usable and four compiled** pilot gates. The batch-size flag remains off by default and no rollout is justified.

The [frozen plan](plan.json) SHA-256 is `c0774eff26fa5d7d785fd0649483694408e7d9cb9f83468002053be6b7e1df6a`; [capture](capture.json) SHA-256 is `3fd74b140c2137278f72e54101cf67f102f5c710e7cd9c1626e2e020d462a155`. The independently reviewed [preflight](INDEPENDENT_REVIEW.md) passed 27 socket-blocked harness tests and a separate one-shot freshness check verified the intended AWS account with 898 seconds of credential life before freezing. The final candidate source passed **1,365 backend tests**. The freshness check made one STS identity request with bounded Signin refresh activity; execution separately verified the account before its four Converse calls. Two call slots remained unattempted.

The full job took **203.505/240 seconds** and reported **16,205 input + 15,746 output tokens**. There was no provider timeout, malformed JSON, truncated response, call-budget breach, or missing usage. The second author again requested three rather than two because the first pass released zero questions. [Structural replay](STRUCTURAL_REPLAY.md) traces six sanitized prose candidates, three first-pass `invalid_feedback` rejections, three verified returns, and no compiled sidecars.

The [five-slot keyless worksheet](blind-worksheet.json) included two unavailable placeholders. Two independent answer and pair reviews were [locked before unblinding](blind-lock.json) (SHA-256 `833a0547dcce3f5c69fbc2463d9b3da18cab736eefef27584714a293dc531f47`). Their answers matched the explicit keys for all three returns in the [joined review](unblinded-review.json). The [post-lock content audit](POST_REVIEW.md) found all three learner-facing explanations mathematically sound, all four choices distinct, and the stated difficulty and scope appropriate. The two unfilled original slots retain zero credit. These findings support **3/5 content-usable prose returns**, not a compiler or full-worker qualification.

The earlier five-item current-source run failed differently: its numerical author exhausted 16,000 output tokens in 188.839 seconds and returned truncated JSON. This pilot is a different model sample, so the change in stop reason is descriptive, not proof that smaller batches generally prevent truncation. It did expose a sharper bottleneck: the existing `constructed_quantitative` native schema permits either prose or typed task rows, and both candidate author calls chose prose. A separate task-only author contract is the next bounded hypothesis for this exact numerical scope. It needs its own schema validation, full-route test, AWS acceptance, and independent content review before any source/default promotion.
