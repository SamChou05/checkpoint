# Generic prose seven-row reserve qualification

The opt-in generic route is pinned to pushed source `a6448403e3067354e040d7386822549f9d9f24bc`. `live_probe.py` provides a source-pinned, one-shot full-worker harness; it has **not been launched**. `protocol.json` and `protocol_guard.py` retain the predeclared inert request and gate. The harness's `--draft` and `--preflight` modes make no AWS calls. Its `--launch-precheck` and `--execute` modes require a frozen plan, exact-hash root and independent review lock, and a fresh identity window. Source pinning covers every imported production service module plus the capture helper and requirements; any later unpinned service import aborts before a provider call.

The fixed synthetic request asks for five self-contained probability questions without a skill map, source document, or adaptive plan. The candidate route must make **one native seven-row prose author call**, retain each source ordinal through adaptation and review, and return the **earliest five accepted rows** after all existing sanitizer, answer-blind complete-choice solver, six-pair distinctness, and authored-teaching reviewer gates. No candidate may be hand-picked from the seven after seeing model output. A partial return is a failed job; there is no retry, repair, fallback, top-up, or second job.

Before a live run, run the socket-free fake-provider replay and freeze `plan.json` from the exact reviewed draft digest. The plan records the pushed source commit and imported service-file hashes, the request's byte hash, seven-row native schema and exact author wire hashes, model/runtime/SDK versions and endpoints, the harness hash, a reviewed Bedrock account/profile, and the predeclared gate below. Have an independent agent review the exact frozen plan and harness hashes and add the matching `review-approval.json` lock. Only then do one bounded STS precheck and one live execution. Do not reuse a prior capture or alter this request to fit output.

The harness uses the existing [bounded capture helper](../../../backend/bedrock-question-service/evals/bounded_bedrock_capture.py). It creates its capture exclusively before credentials; starts a one-shot 240-second `SIGALRM` **before** execute-time credential export and STS; permits at most six durable Converse reservations with one SDK attempt per call, 3-second connect and 200-second read ceilings; and performs one signed STS request at precheck and one at execute on an explicitly checked account and endpoint. It retains credential-checked visible model text for audit, bounded usage, original seven-row status, aggregate quality-rejection counts, and bounded error identities. It omits hidden reasoning, credentials, raw exceptions, and request headers. A failed/interrupted run is final for this trial ID. The ordinary output cap is 6,000 tokens; this Claude adaptive-thinking wire uses the explicit 16,000-token thinking cap, which the runtime places in `inferenceConfig.maxTokens` because reasoning and JSON share that budget.

The official machine gate is **five returned rows from seven original authored ordinals**, five unique keys offered exactly once, policy revision 7 on every returned row, backend difficulty at least 2, all 30 within-question choice pairs meaningfully distinct, sound main explanations, and no strong cross-question repeat. The returned order must be the earliest five surviving source ordinals, with missing/rejected ordinals explicit. This gate is evaluated on the actual captured worker output and rejected when evidence is missing. Two independent reviewers then receive only a shuffled, answer-blind worksheet of the returned five: prompt and four choices, without keys, source ordinals, model/reviewer ratings, or rejection reasons. Each reviewer records the selected key, any second defensible choice, all six within-item pair judgments, self-containment, topic fit, difficulty 2–3, and cross-item repetition. After both answer choices are locked, they inspect the main explanation in a separate reveal and record teaching accuracy. Lock both reviews before opening the private returned-key map. Any disagreement about a key or material uncertainty fails qualification pending a **new** experiment; it does not authorize editing this capture.

This one job can establish that the candidate worked for one fixed request under a bounded budget. It cannot establish a population success rate or a causal advantage over five-row authoring without a separately randomized comparison. The current deployed TestFlight path remains legacy and is outside this experiment.

These are socket-free. `python -B live_probe.py --draft` prints the exact digest required by `--freeze`; freezing writes only a local plan and makes no AWS call.
