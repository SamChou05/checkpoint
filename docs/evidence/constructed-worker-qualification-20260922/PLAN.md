# Draft constructed-quantitative worker qualification

This is **unfrozen and unrun**. Root must approve the exact final source and plan
before any provider dispatch. No model activation, account change, bank write or
deployment is part of the trial. Existing failed captures and their prospective
criteria remain unchanged.

The candidate changes the quantitative author variant to a task-only contract:
`QUESTION_AUTHOR_MODE=constructed_quantitative`, native
`question_author_constructed_v1`. The model supplies a bounded exact-value or
explicit integer-domain scalar task, with no numerical choices, key, stem or
teaching. The deterministic constructor produces the four options and the
existing compiler derives all five learner fields. Invalid tasks, unsupported
domains, insufficient distinct wrong-option pools and overlong proofs fail
closed; no author prose can repair the same row. Ordinary subject rows remain
available under the existing prose shape.

The initial draft uses the completed constructor integration checkout as its
candidate source. All **27 runtime modules**, dependencies, helper bytes and
schema configurations are pinned, including the new pure constructor. Root may
later choose a separately qualified prose author prompt before freezing; such a
change must be explicitly recorded and reviewed, not silently included in this
draft's stated author-contract-only comparison.

Reuse the three exact normalized requests from the completed compiled-proof
trial, byte-identical to the original mixed-route jobs: five numerical tasks,
five Python expression questions, and five mixed arithmetic/English questions
with a three/two skill allocation. Difficulty is at least two. The original
denominator is **15** regardless of raw top-up row counts. These are fresh
generations on repeated scopes, not a matched causal comparison or new-domain
generalization.

Run each job once through the actual `_generate_sanitized_questions`, with its
normal top-ups, deduplication, partial returns and conservative pass-admission
rules. Each gets six provider reservations and a fresh 240-second deadline; the
global cap is 18 calls. Pure compiled passes normally use author plus final
audit; prose additionally uses the answer-blind fixed-pair solver. A new mixed
author pass still requires capacity for three calls because its output may
contain prose. Unused reservations never authorize a harness rescue.

All non-author-mode settings remain exactly those of the completed compiled-proof
trial: Kimi K2.5 author, thinking disabled, 6,000 tokens, temperature 0.2; Sonnet
4.6 solver and auditor, adaptive/high, 16,000 shared tokens, no sampling fields.
Native prose solver v5 and immutable issue-flag audit v3 retain their existing
count-bound schemas. Their source-selected request/configuration bytes are
verified at actual dispatch. Use the actual client factory with a 100-second
read ceiling that shrinks with remaining worker time, three-second connect
timeout, and one SDK attempt. There is no fallback model or guardrail override.

Unchanged prospective requirements:

- At least 14/15 returned, at least four per job, within each job's real deadline
  and the provider ceilings.
- At least six returned compiled questions: four quantitative and two mixed;
  mixed must also retain at least one correctly assigned English prose item.
  Python must test Python semantics, not replace the objective with arithmetic.
- Every returned item has a unique exact key, meaningfully distinct and plausible
  options, sufficient premises, assignment fit, appropriate difficulty and sound
  learner teaching. Assess the **literal stem and all choices**. Do not invent a
  hidden minimum, grammatical-consistency condition, preferred placement or
  interpretation to rescue an otherwise ambiguous question. Uncertainty fails
  the item under the same prospective standard.
- All five compiled learner fields must reproduce exactly from the trusted final
  specification and remain unchanged through release. The raw quantitative row
  must never contain options or a key. Prose must retain its exact authored main
  and an empty choice-feedback map. Expected revisions remain compiled 8 and
  prose 7; generated flags or hashes cannot establish compiler provenance.
- Every compiler/prose survivor receives the immutable final audit. Compiler
  proof skips only the redundant model solver. Final audit scope, difficulty,
  novelty, key agreement, feedback support and other vetoes remain intact.
- All failed and unattempted slots remain in the original denominator. Provider,
  model, deadline or quota failures follow actual bounded runtime behavior;
  independent jobs continue unless a global integrity/setup condition occurs.
  Credentials/setup, source/request/provenance drift, capture tampering or actual
  budget violations stop globally. No extra call, retry, replacement or resume.

The harness preserves its reviewed capture boundaries: pre-import runtime/helper
hashes; source checks before/after dispatch and completion; durable reservations
and request capture before Converse; exact model/transport guards; exclusive
execution; external capture-change detection; bounded safe errors and visible
response filtering; omitted reasoning/signatures; raw and decoded-JSON
credential-echo checks before retaining visible text or adapting it. The latter
uses the runtime's exact newline-joined text, including Unicode escape decoding,
and scans duplicate members without allowing one to hide another. Malformed JSON
remains an ordinary native model failure; scanning does not approve or repair it.
Missing usage is unknown, not zero.

Provenance uses current-pass sanitizer bindings and actual retained verifier
objects. Compiled sidecars bind the raw task's ordinal to the full constructed
spec and exact learner fields; ordinary prose retains exact raw main matches.
No global text search, model approval flag or hash comparison substitutes for
actual object/source association. A supplied-choice quantitative row is a native
contract failure, not a fallback to the older mixed author mode.

Offline checks adapt all prior guard fixtures to real task-only author rows and
exercise the actual constructor. Add insufficient-pool failures alongside valid
siblings, supplied-choice rejection, unchanged mathematical tasks and recompiled
learner content. Existing quota/deadline, top-up/dedup, metadata, strict contract,
capture-drift and source/transport/setup guards remain required. Test fixtures
use synthetic provider judgments and are not semantic model evidence.

After capture completes, project returned stems/choices using the unchanged
key-independent worksheet helper and lock independent literal-task solving before
unblinding keys and teaching. Structural replay, reviewer declarations, private
reason fidelity, latency and yield are reported separately. No successful format
check substitutes for the independent content standard. A passing run supports
only these three fresh batches on repeated scopes, not universal semantics or a
deployed worker/inventory claim.
